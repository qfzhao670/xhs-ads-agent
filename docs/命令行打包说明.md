# 打包说明

## Windows 安装包（推荐）

Windows 安装包由 GitHub Actions 在 Windows Runner 中生成，本地不需要 Windows 电脑。

### 手动打包

1. 将代码提交并推送到 GitHub。
2. 打开 GitHub 仓库的 `Actions` 页面。
3. 选择 `Build Windows installer` 工作流。
4. 点击 `Run workflow`，再确认运行。
5. 等待 `Windows x64` 任务完成。
6. 在该次运行页面下方的 `Artifacts` 中下载 `xhs-workshop-windows-x64`。
7. 解压后的 `小红书运营自动化工坊-Setup-<版本>-x64.exe` 就是 Windows 安装程序。

Actions 中的打包产物保留 14 天，下载后可以单独存档或分发。

### 发布到 GitHub Releases

手动点击 `Run workflow` 只会生成 Actions Artifact。工作流在推送 `v*` 格式的 Git 标签时，会自动创建同名 GitHub Release、生成发布说明，并上传 Windows 安装包。

不要只运行 `git tag v1.4.1`。如果没有同时更新项目版本号，Release 虽然会叫 `v1.4.1`，但安装包文件名和应用内部版本仍可能是旧版本。

#### 标准发布流程

以将当前版本发布为 `v1.4.1` 为例。

1. 切换到 `main` 分支并同步远程代码：

```bash
git switch main
git pull --ff-only origin main
```

2. 确认没有未提交的修改：

```bash
git status
```

`npm version` 需要在工作区干净时执行。如果有需要发布的修改，应当先提交它们。

3. 更新版本号，并自动创建版本提交和 Git 标签：

```bash
npm version 1.4.1 -m "release: v%s"
```

该命令会一次完成：

- 将 `package.json` 的版本更新为 `1.4.1`；
- 同步更新 `package-lock.json`；
- 创建一个 `release: v1.4.1` Git 提交；
- 创建 `v1.4.1` Git 标签。

4. 推送版本提交和标签：

```bash
git push origin main --follow-tags
```

也可以分开推送：

```bash
git push origin main
git push origin v1.4.1
```

5. 打开 GitHub 仓库的 `Actions` 页面，等待由 `v1.4.1` 标签触发的 `Build Windows installer` 工作流完成。

6. 打开仓库的 `Releases` 页面，确认 `v1.4.1` Release 中已有 `小红书运营自动化工坊-Setup-1.4.1-x64.exe`。

如果只想根据当前版本自动增加版本号，也可以使用：

```bash
npm version patch   # 1.4.0 -> 1.4.1
npm version minor   # 1.4.0 -> 1.5.0
npm version major   # 1.4.0 -> 2.0.0
```

每次只执行其中一条。执行后仍然需要通过 `git push origin main --follow-tags` 推送提交和标签。

标签版本应当始终与 `package.json` 的 `version` 保持一致。如果重新运行同一标签的工作流，已有 Release 的附件会被更新。

### Windows 电脑本地打包

如果以后有 Windows 环境，可以在项目目录执行：

```powershell
npm ci
npm test
npm run dist:win
```

安装包会生成在 `release` 目录。

> 未配置 Windows 代码签名时，安装包仍可生成和使用，但 Windows SmartScreen 可能显示“未知发布者”警告。

## macOS 本地打包

在终端进入项目目录：

```bash
cd /Users/zhaoqifan/Code/xhs-ads-agent
```

首次运行或依赖有变化时，先安装依赖：

```bash
npm install
```

建议先检查代码能否正常构建：

```bash
npm run check
```

打包当前 macOS 架构的安装包：

```bash
npm run dist
```

打包完成后，DMG 和 ZIP 会生成在项目的 `release` 目录中。在 macOS 上运行 `npm run dist` 不会生成 Windows 安装包。

如果只想生成未封装成安装包的应用目录，可以运行：

```bash
npm run package
```
