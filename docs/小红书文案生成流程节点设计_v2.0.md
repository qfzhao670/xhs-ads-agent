# 小红书文案生成流程节点设计 v2.0

> 版本：2.0  
> 日期：2026-10-30  
> 状态：产品与技术设计稿  
> 替代版本：`小红书文案生成流程节点设计_v1.4.md`

## 0. 结论先行

v2.0 不应只是在现有提示词中增加一句“写得隐晦一点”，而应调整整个生成链路：先选内容模式，再把完整业务拆成可持续生产的“小选题”，最后才生成文案。

本版建议落实以下五个核心变化：

1. 将文案分为“显式宣传”和“生活化种草（原隐式宣传）”两条独立链路，用户每轮生成前必须先选模式。
2. 生活化种草默认只解决一个生活问题、使用一个核心角度、承接一至两个业务点，不再完整介绍产品。
3. 将“业务真实性”与“创意发散”拆开：业务主张必须来自已确认事实，香港、澳门等生活场景、文化背景、情绪和选题可以合理发散，但不得把模型想象伪装成客户行程、亲身经历或已承诺服务。
4. 所有包含自然语言输入的环节，都把“用户本轮明确要求”设为最高创作指令；仅法律、平台规则和已确认业务事实构成不可越过的硬边界。
5. 新增“终稿内容库”和“确认入库”节点。入库内容按两种模式分池管理，后续生成默认不得重复同池中已经使用过的核心策略；去重只分析文字，不分析图片。

“生活化种草”不是“隐藏广告身份”。它指的是内容结构更原生、更有生活价值，不是伪装素人、编造体验或规避商业标识。小红书社区公约强调真实分享、反对虚假人设和伪装普通用户进行不当营销；法律也要求互联网广告具有可识别性。因此产品界面可以保留“隐式宣传”作为用户易懂的说明，但正式模式名建议使用“生活化种草”。

## 1. 为什么 v1.4 容易生成“产品总纲”

v1.4 的事实提取是正确的，但后续节点把“完整业务事实”整体交给策略模型，并要求模型围绕这些事实生成策略。模型会自然地把信息完整度理解成质量，继而出现以下问题：

- 每个策略都想覆盖产品、流程、价格、优势、适合人群和联系方式；
- 不同策略只是换标题和语气，底层信息结构高度一致；
- 为了“不得补充事实”，模型不敢围绕香港、澳门继续扩展生活场景；
- 修改阶段要求“保持同一策略”，即使用户明确要求换角度，也可能被旧策略压制；
- 已确认内容没有进入后续生成的排除上下文，长期运营会不断重复相似选题。

问题根源不是模型写作能力，而是流程把“一份完整业务资料”直接映射成“一篇完整文章”。v2.0 应在两者之间增加“内容模式”和“微选题”两层。

## 2. 平台调研结论及对系统的直接影响

以下结论以 2026-10-30 可查到的官方规则与帮助中心为主要依据。

| 平台信号 | 对生成系统的影响 |
| --- | --- |
| 小红书社区强调真实、有用、文题相符，反对虚假人设、夸张猎奇、伪装普通用户营销和滥发广告。 | 生活化内容应像真实生活建议，但不能自动使用“亲测”“我带娃去了”“真实体验”等第一人称经历，除非用户提供了相应事实。 |
| 平台将产品种草、客资收集、种草直达等视为不同营销诉求，并分别衡量阅读、互动、搜索组件点击、搜后阅读等指标。 | 策略生成时不应让每篇笔记同时承担认知、种草、留资和成交。生活化种草侧重生活价值与自然承接；显式宣传可以承担更完整的产品说明或转化。 |
| 官方内容方法提到根据产品阶段做内容定位、在笔记中自然预埋关键词，并通过标题和封面提高点击。 | 策略卡中应增加“用户搜索问题/关键词”和“这篇只解决什么”，关键词要服务具体问题，不做机械堆砌。 |
| 合作笔记审核会检查标题党、文题不符、联系方式导流、推广意图不明确等问题。 | 生活化种草既不能把联系方式和价格硬塞进正文，也不能完全切断内容与业务的关系。应保留一个清晰但轻量的“业务承接点”。 |
| 平台鼓励标明 AI 参与创作。 | 系统应在项目设置中提供“AI 辅助创作标识”选项，并在发布前检查清单中提醒用户按账号类型和平台最新规则处理。 |
| 互联网广告应具有可识别性；通过知识介绍、体验分享、消费测评等形式推销商品或服务并附加购买方式时，需显著标明广告。 | “生活化种草”只能降低广告腔，不能被设计成规避广告标识或商业合作披露的工具。系统应根据账号身份、合作关系和是否附加购买方式显示合规提醒。 |

这意味着小红书运营不应追求“每一篇都把产品讲清楚”，而应追求：每篇只完成一个用户任务，多篇共同建立认知、搜索覆盖和信任。

### 2.1 推荐的长期内容组合

系统不应把以下比例写成平台官方规则，但可以作为项目级运营建议：

- 生活问题型：解决一个具体问题，例如“秋假只有几天，亲子安排怎么不浪费”；
- 决策辅助型：比较一种选择的适用人群、优缺点或准备重点；
- 场景灵感型：提供城市、季节、家庭关系或成长目标相关的灵感；
- 体验细节型：只讲一个能被感知的细节，但必须有真实素材支持；
- 显式说明型：在需要承接搜索、咨询或活动说明时，完整介绍产品的一部分或整体。

同一个产品可以被拆成几十个生活问题，而不是反复生成几十篇“产品介绍”。

## 3. v2.0 的五条设计原则

### 3.1 一篇只承担一个主要任务

每篇文案生成前必须形成一个“选题原子”：

```text
一个目标人群
+ 一个具体时刻或触发场景
+ 一个真实问题/情绪
+ 一个读者看完能获得的价值
+ 一个轻量业务承接点
= 一篇小红书笔记
```

例如：

```text
目标人群：正在规划秋假的家长
触发场景：假期不长，不想只在周边玩
真实问题：怎样同时兼顾孩子见识和家庭陪伴
内容价值：给出“短假期也可以做跨城成长体验”的新思路
业务承接：港澳研学适合作为一种选择，并解释一至两个优势
```

正文不再自动展开完整行程、每日安排、价格、报名方式和所有权益。

### 3.2 两种模式是两套内容契约，不是两种语气

| 维度 | 显式宣传 | 生活化种草（隐式） |
| --- | --- | --- |
| 核心任务 | 说明产品、活动或服务 | 先解决生活问题，再自然连接产品 |
| 产品出现位置 | 可在标题或开头明确出现 | 默认在正文中后段自然承接，不强制标题出现 |
| 单篇业务点 | 可使用 3–5 个，但仍需有主次 | 默认 1 个，最多 2 个 |
| 价格、联系方式、产品形态 | 按用户要求和合规规则决定 | 默认不写；只有用户本轮明确要求才写 |
| 行程/流程 | 可做概要介绍 | 默认不写完整流程，不按“第一天、第二天”铺陈 |
| CTA | 可明确咨询、了解、报名，但必须合规 | 默认使用弱 CTA，例如“可以把它列入备选”，也可无 CTA |
| 创意发散 | 围绕事实进行有限扩展 | 可大量扩展生活场景、问题、情绪和城市内容 |
| 去重池 | 仅与显式宣传终稿比较 | 仅与生活化种草终稿比较 |

### 3.3 事实边界与创意空间必须分层

系统不再使用笼统的“不得补充任何事实”，而使用以下四层信息模型：

| 层级 | 含义 | 是否允许模型扩展 | 示例 |
| --- | --- | --- | --- |
| A. 已确认业务事实 | 客户实际提供或用户确认的产品、服务、权益、价格、资质、行程、名额等 | 不允许自行扩展 | “项目包含香港、澳门相关研学内容” |
| B. 稳定公共背景 | 不指向客户承诺的通用地理、文化、生活方式背景 | 可以合理扩展 | 港澳城市节奏、跨文化观察、亲子讨论主题 |
| C. 创意表达 | 选题、假设场景、问题、比喻、情绪和内容结构 | 可以自由扩展 | “秋假不想只换个地方写作业，可以怎么安排？” |
| D. 时效或高风险外部事实 | 政策、签注、票价、营业时间、交通班次、实时活动、安全承诺等 | 未核验不得写成确定事实 | 具体通关政策、当前票价、某场馆开放时间 |

模型可以“脑补”B 和 C，但不得把它们写成 A，也不得在没有真实依据时制造第一人称体验。D 类内容若系统没有联网核验能力，应标为“待核验”，或避开具体数字和结论。

### 3.4 用户自然语言是最高创作指令

所有带有自然语言输入的功能必须使用同一套优先级：

```text
P0：法律法规、平台硬规则、已确认业务事实
P1：用户当前这一次输入的明确要求
P2：用户在本轮较早输入且未被撤销的要求
P3：用户选择的内容模式与策略
P4：项目关键词、参考文案、终稿库避重要求
P5：系统默认写法和风格偏好
```

其中 P1 是最高“创作”指令。P0 不是创作偏好，而是系统不能突破的真实性与合规边界。

具体规则：

- 当前指令与旧指令冲突时，以当前指令为准；
- 用户说“换一个角度”时，允许离开原策略，不能再强制“保持同一策略”；
- 用户明确要求删掉品牌名、价格、CTA 时，系统默认模板不得重新补回；
- 用户要求加入未被确认的业务承诺时，不得静默编造，应指出冲突并请用户确认事实；
- 用户指令没有被完全执行时，模型必须返回未执行项及原因，前端清晰展示，不能假装已遵循；
- 参考文案、关键词、历史高表现结构只能辅助，不能覆盖用户当前要求。

### 3.5 入库意味着进入“后续避重范围”

“确认文案”只表示当前版本可继续制作配图；“确认入库”才表示这篇内容被认定为最终资产，并参与以后生成的重复检测。

两次确认不能合并，因为用户可能在配图阶段发现文案与视觉不匹配并再次修改。

## 4. v2.0 用户流程总览

```text
01 准备素材
    ↓
02 提取并核对业务事实
    ↓
03 选择内容模式
    ├─ 显式宣传
    └─ 生活化种草（隐式）
    ↓
04 生成微选题策略候选
    ├─ 从公共背景和生活场景发散
    ├─ 读取同模式终稿库做避重
    └─ 每个策略只解决一个问题
    ↓
05 用户选择策略并输入自然语言要求
    ↓
06 生成文案
    ↓
07 人工审核与自然语言修改循环
    ↓
08 制作配图（可以跳过）
    ↓
09 确认入库
    ├─ 保存最终文字与已有图片
    ├─ 生成文字策略指纹
    └─ 进入后续同模式避重范围
```

左侧主导航调整为：

```text
文案生成
终稿内容库   ← 新增
素材管理
设置
```

## 5. 节点详细设计

### 节点 01：准备素材

沿用 v1.4 的项目制和素材管理方式。原始素材、关键词库、参考文案库、合规准则和图片参考库仍属于项目资产。

新增一项项目级设置：

- 账号/发布身份：品牌专业号、员工/KOS、合作博主、普通创作者、暂未确定；
- 是否涉及商业合作或利益关系；
- 是否准备附加商品、购买链接或咨询组件；
- AI 辅助创作标识提醒是否开启，默认开启。

这些信息不用于“增加广告腔”，而用于最终合规提醒。

### 节点 02：提取并核对业务事实

完全保留现有的事实提取、宣传表达识别、冲突处理和输出结构，不增加事实风险等级或新的事实分类字段：

```json
{
  "confirmedFacts": [
    {
      "category": "服务范围",
      "items": ["包含香港、澳门相关研学内容"]
    }
  ],
  "promotionalExpressions": [],
  "conflicts": []
}
```

事实提取提示词仍要禁止补充业务事实，但该限制只作用于本节点，不应继续被错误地解释为“后续不能创造生活选题”。业务事实与创意发散的边界由后续节点和全局提示词负责，不在本节点增加额外风险等级。

### 节点 03：选择内容模式

这是 v2.0 新增的必选节点，位于事实确认之后、策略生成之前。

#### 3.1 模式选择卡

**显式宣传**

- 适合：产品介绍、活动发布、项目答疑、转化承接；
- 默认：产品名称可以明确出现，允许较高信息密度；
- 提醒：仍应有一个核心主题，不等于机械堆信息。

**生活化种草（隐式）**

- 适合：生活灵感、问题解决、场景建议、认知建立、搜索覆盖；
- 默认：不在标题硬塞产品名，不写价格和联系方式，不完整介绍产品；
- 提醒：不是伪装素人或隐藏商业关系。

#### 3.2 可选自然语言

提供“这篇你最想怎么写”输入框。示例占位文案：

> 例如：写给正在安排秋假的初中生家长，从“短假期也能打开孩子眼界”切入，不要出现价格、报名和每天行程。

这段输入从此节点开始进入 P1/P2 用户指令区，并原样保存，不应被系统摘要后替代。

### 节点 04：生成微选题策略候选

本节点内部拆为三个子步骤，但用户只看到一次生成过程。

#### 4A. 建立本轮创意空间

模型根据已确认业务事实，扩展以下内容：

- 可关联的人群；
- 生活时刻和季节节点；
- 用户可能搜索的问题；
- 情绪、犹豫和决策障碍；
- 与地点、文化和日常生活有关的稳定公共背景；
- 可被收藏的实用信息结构；
- 与业务自然连接的轻量承接方式。

这里明确允许模型发散，但输出必须给每一项标注来源类型：`business_fact`、`public_context` 或 `creative_hypothesis`。

#### 4B. 读取同模式终稿库并建立排除清单

只读取与本轮模式相同的入库内容：

- 显式宣传只读取显式宣传库；
- 生活化种草只读取生活化种草库；
- 图片不进入相似度计算，也不进入文案去重提示词；
- 优先召回与本轮人群、场景、问题或地点相近的历史内容，而不是把全部终稿塞进提示词。

召回结果转为简短排除清单，例如：

```text
已经使用过，不要再次生成：
1. “秋假时间短，港澳研学比远途旅行更省时间”的角度；
2. “第一次带孩子去香港需要准备什么”的清单结构；
3. “把旅行变成课堂”的价值主张与问句开头组合。
```

#### 4C. 生成 3–5 个微策略

生活化种草策略必须满足：

- 只有一个核心问题；
- 只有一个主要内容收益；
- 默认只使用一个业务卖点，最多两个；
- 不生成完整产品介绍；
- 不默认写价格、联系方式、完整行程和报名流程；
- 与已入库同模式内容存在可解释的差异；
- 标题方向与正文内容一致；
- 至少有一个自然的搜索短语，但不堆砌关键词。

显式宣传策略可以使用更多业务信息，但仍需区别于历史策略，且每个策略要有明确主线。

策略输出结构建议：

```json
{
  "strategies": [
    {
      "id": "STR-0001",
      "mode": "native_seeding",
      "name": "秋假不长，也能给孩子一次跨文化观察",
      "targetAudience": "正在安排秋假的初中生家长",
      "triggerMoment": "秋假临近、假期天数有限",
      "coreQuestion": "短假期怎样兼顾放松和见识增长",
      "readerValue": "获得一种不同于周边游和长途游的安排思路",
      "businessBridge": "自然提到港澳研学是一种可选方案",
      "businessFactIds": ["FACT-0012"],
      "creativeContexts": [
        {
          "text": "从城市差异中引导孩子观察公共空间和生活节奏",
          "sourceType": "public_context"
        }
      ],
      "searchPhrases": ["秋假怎么安排", "亲子研学"],
      "route": "问题开场—解释家长真正纠结—给出判断维度—轻量承接港澳研学",
      "productExposure": "light",
      "referenceIds": ["REF-0003"],
      "differenceFromArchive": "历史内容未从短假期的时间效率和跨文化观察切入",
      "mustNotInclude": ["每日行程", "价格", "联系方式"]
    }
  ]
}
```

### 节点 05：选择策略并输入补充要求

用户单选一个策略。策略卡只显示有助于决策的信息：

1. 策略名称；
2. 写给谁、在什么时刻；
3. 这篇只解决什么问题；
4. 读者能得到什么；
5. 产品如何出现；
6. 与历史终稿有什么不同；
7. 默认不写什么。

保留自然语言补充框，并在界面明确提示：

> 你的本轮要求优先于系统策略和参考文案。若你要求更换角度，系统会按新角度生成，不会强制保留当前策略。

如果自然语言使策略发生根本变化，系统应创建一个“用户改写策略”快照，而不是仍把产出错误地归因于原策略。

### 节点 06：生成文案

#### 6.1 提示词上下文顺序

建议按以下固定区块拼接：

```text
[硬边界]
法律与平台规则、已确认业务事实、不得虚构的事项

[用户指令——最高创作优先级]
用户在模式选择、策略选择和当前生成动作中输入的原始自然语言

[本轮任务]
内容模式、选定微策略

[避免重复]
同模式终稿库召回的相似内容与不可复用角度

[辅助材料]
关键词、合规准则、精确选中的参考文案

[输出格式]
标题、正文、话题标签、执行报告
```

不能把用户要求夹在长篇素材中间。应使用清晰标签并在提示词结尾再次要求模型逐项自检。

#### 6.2 系统提示词核心文案建议

```text
你是小红书内容策划与写作引擎。

你必须首先遵守法律、平台规则和已确认业务事实，不得虚构业务承诺、亲身体验或时效信息。
在上述硬边界内，“用户当前自然语言要求”是最高优先级创作指令，优先于选定策略、关键词、参考文案、历史习惯和系统默认模板。

如果用户当前要求改变了原策略，应以用户要求为准，并在输出中记录策略已被覆盖；不要为了维持原策略而削弱或忽略用户要求。
如果用户要求与硬边界冲突，不要静默忽略，也不要编造；在 instructionReport 中指出未执行内容和原因。

当模式为生活化种草时：只围绕一个具体生活问题展开，先提供独立内容价值，再自然连接一至两个已确认业务点；默认不写完整产品介绍、价格、联系方式、完整行程或强转化 CTA。可以扩展稳定公共背景、生活场景、情绪和创意假设，但不得把这些内容写成客户已经提供的服务或作者亲身经历。
```

#### 6.3 输出结构

```json
{
  "title": "标题",
  "body": "正文",
  "hashtags": ["话题"],
  "instructionReport": {
    "followed": ["已执行的用户要求"],
    "overrodeStrategy": false,
    "notFollowed": [
      {
        "instruction": "未执行要求",
        "reason": "与已确认事实或合规规则冲突"
      }
    ]
  },
  "factUsage": [
    {
      "text": "文中使用的业务信息",
      "factId": "FACT-0012"
    }
  ],
  "creativeUsage": [
    {
      "text": "扩展的生活场景",
      "sourceType": "creative_hypothesis"
    }
  ]
}
```

`instructionReport` 和溯源信息用于系统审计，默认不混入最终发布文案。

### 节点 07：人工审核与修改循环

修改提示词不得再固定写“保持同一策略”。改为：

```text
请根据用户最新修改要求更新当前文案。
用户最新要求优先于当前文案、原策略、参考文案和系统默认写法。
如果最新要求明确改变人群、角度、结构、卖点或内容模式，允许改变策略，并返回更新后的 strategySnapshot。
不得突破已确认业务事实和合规硬边界。
```

修改分为两类：

- 局部修订：标题、措辞、长度、段落、语气等不改变核心策略；
- 策略改写：人群、问题、内容模式、核心卖点或承接方式发生变化，系统生成新的策略快照并重新执行避重检查。

前端无需要求用户理解这两个概念，系统自动判断即可，但应在版本记录中标明“局部修订”或“策略已变更”。

用户点击“确认文案”后：

- 该版本被锁定为当前配图依据；
- 可以进入配图；
- 尚未进入终稿内容库；
- 如果再次编辑，原配图标记为“可能与文案不一致”。

### 节点 08：制作配图

沿用现有的参考图库驱动图生图链路，但做三点调整：

1. 配图策划只读取本篇最终文案实际使用的业务事实，不要因为项目事实很多而在图片中补回产品总纲；
2. 生活化种草的封面优先表达生活问题、场景或情绪，不默认做产品海报；
3. 图片是否相似不影响文案去重。终稿库保存图片只用于查看、导出和复用，不参与后续“策略完全一致”的判断。

允许用户跳过配图直接入库。此时内容库显示“无配图”；后续可以补图，但补图不会改变文字去重指纹。

### 节点 09：确认入库

在“制作配图”之后新增独立流程按钮：`确认入库`。

点击后显示不可忽略的确认弹窗：

> 入库后，这篇文案的核心选题、目标人群、切入问题和产品承接方式将进入后续避重范围。系统默认不会再生成策略完全一致的内容。图片不会参与重复判断。是否确认入库？

弹窗展示：

- 内容模式；
- 标题；
- 核心问题；
- 业务承接点；
- 已有配图数量；
- 将写入的终稿库分区。

入库后：

- 保存最终文字、已有图片引用、策略快照、事实引用和用户指令；
- 生成文字规范化哈希和策略指纹；
- 状态改为 `archived`；
- 默认禁止直接修改。用户要修改时创建新版本，并重新确认入库；
- 用户可以“移出终稿库”，移出后不再参与避重，但必须二次确认并保留操作记录。

## 7. 文字去重与“策略一致”判定

只比较标题、正文、标签和结构化策略，不比较图片。

### 7.1 三层判定

#### 第一层：完全相同文本

对文字做以下规范化后计算哈希：

- 去除首尾空格和多余空行；
- 统一全角/半角标点；
- 统一标签顺序前的格式；
- 不删除有实际意义的数字、地点和产品名。

规范化哈希相同，直接阻止自动入库或自动生成。

#### 第二层：高度相似文案

比较标题和正文的语义向量。建议初始阈值：

- 相似度 `>= 0.92`：判为高度相似，自动重新生成；
- `0.82–0.92`：进入策略维度复核；
- `< 0.82`：一般不因文本相似度阻断。

阈值必须通过实际终稿库校准，不应写死在提示词中。

#### 第三层：策略指纹

策略指纹至少包括：

```text
内容模式
目标人群
触发时刻
核心问题
读者收益
主要业务点
产品承接方式
叙事结构
标题钩子类型
结尾意图
```

若“目标人群 + 核心问题 + 业务承接方式”三项基本一致，即使文字不同，也视为策略重复并重新生成。

同一个大主题不等于重复。例如以下内容可以同时存在：

- 秋假时间短，为什么港澳适合作为跨城体验备选；
- 第一次让孩子观察两种城市公共空间，可以看什么；
- 不想把研学做成打卡，家长可以先问孩子哪三个问题。

它们都涉及港澳研学，但解决的问题和读者收益不同。

### 7.2 候选策略阶段就避重

不能等成稿后才发现重复。策略候选生成后先做指纹比较：

```text
候选策略
  ↓
召回同模式相似终稿
  ↓
规则与语义判定
  ├─ 重复：丢弃并补生成
  ├─ 可疑：模型说明差异，再决定保留或补生成
  └─ 不重复：展示给用户
```

### 7.3 用户明确要求复用历史方向

默认绝不自动重复。如果用户在自然语言中明确说“沿用某篇”“继续这个系列”或“用同一个角度重写”，则 P1 用户指令生效：

- 系统显示“你正在主动复用已入库方向”的提示；
- 保存 `duplicateOverride: true` 和用户原始指令；
- 仍应避免逐句改写或近似复制，除非用户明确要求编辑原稿；
- 入库时再次提示该内容与哪篇历史终稿接近。

这样既满足默认不重复，也不违背“用户自然语言优先”。

## 9. 提示词改造清单

### 9.1 全局系统提示词

当前系统提示词中的：

> 只根据用户提供的信息工作，不得补充、猜测或虚构任何业务事实。

建议改为：

> 不得补充、猜测或虚构产品、服务、价格、行程、权益、资质、名额、效果、联系方式等业务事实。可以根据已确认事实扩展稳定公共背景、生活场景、用户问题、情绪和创意表达，但必须与业务承诺区分，不得伪造亲身体验或把想象写成客户已提供的服务。

### 9.2 策略提示词

新增：

- 读取内容模式；
- 原样读取用户自然语言；
- 生活化种草限制业务点数量；
- 读取同模式历史终稿排除清单；
- 输出微选题字段和 `differenceFromArchive`；
- 允许使用公共背景与创意假设；
- 禁止完整产品总纲。

### 9.3 成稿提示词

新增：

- 用户自然语言独立置顶区；
- 指令优先级声明；
- `instructionReport`；
- 事实使用和创意使用溯源；
- 生活化模式的产品曝光限制；
- 历史内容避重上下文。

### 9.4 修改提示词

删除“保持同一策略”的绝对要求，允许用户最新指令覆盖策略，并触发新策略快照和重新避重。

### 9.5 配图提示词

新增：

- 配图只表达本篇选题，不回填完整业务事实；
- 生活化种草封面避免默认产品海报化；
- 用户视觉修改要求同样高于默认视觉策略，但不得突破真实性和合规边界。

## 10. 香港、澳门场景的正确发散示例

### 10.1 已确认业务事实

```text
业务提供香港、澳门相关研学内容。
```

### 10.2 可以发散

- “秋假不长，怎样让孩子在几天里接触不同城市气质”；
- “一次跨城市观察，可以让孩子关注哪些公共空间细节”；
- “不想把研学做成景点打卡，出发前可以和孩子讨论什么”；
- “家长真正想要的也许不是多去一个地方，而是孩子开始主动提问”；
- 港澳作为跨文化观察、城市生活比较、家庭共同探索的选题背景。

### 10.3 不可以自行生成

- 客户未提供的具体学校、机构、导师、住宿、保险或接待资源；
- 未确认的“第一天香港、第二天澳门”等行程；
- 实时签注、票价、开放时间或交通班次；
- “我们已经带过几百个孩子”“孩子回来都改变了”等效果或案例；
- “我刚带孩子体验完”之类虚构第一人称经历。

### 10.4 推荐成稿方向

```text
标题：秋假不长，也能让孩子换一种眼光看城市

正文先讨论家长面对短假期的真实纠结，再提出“旅行不一定要去得远，关键是有没有新的观察任务”，接着自然提到港澳研学可以成为一种选择，只解释“距离和城市差异带来的观察价值”一至两个点，最后以“先想清楚希望孩子带着什么问题出发”收尾。
```

不自动补充完整产品形态、价格、报名和逐日安排。

## 11. 异常与边界处理

| 情况 | 系统处理 |
| --- | --- |
| 用户没有选择内容模式 | 不生成策略，提示先选择模式。 |
| 生活化模式要求“把所有产品信息都写进去” | 用户当前自然语言优先，将其视为明确覆盖模式默认值；界面提示内容可能更接近显式宣传，并询问是否自动切换模式，但不静默忽略。 |
| 用户要求编造案例、体验或业务承诺 | 不执行，展示与真实性边界的冲突。 |
| 模型生成策略全部与历史内容重复 | 自动扩大人群、时刻、问题或内容收益维度再生成；仍失败时提示终稿库覆盖已很密集，并展示可拓展维度。 |
| 用户修改后改变核心策略 | 创建新策略快照，重新做同模式避重。 |
| 文案确认后又修改 | 原确认失效；相关配图标记“可能不一致”。 |
| 没有配图 | 允许入库，内容库显示“无配图”。 |
| 入库后发现错误 | 创建修订版本并重新入库；原版本保留审计记录，不直接覆盖。 |
| 用户移出终稿库 | 二次确认；内容不再参与后续避重，但历史操作保留。 |
| 终稿库内容很多 | 先用结构化字段和向量召回最相近的少量内容，不把全库塞入提示词。 |

## 12. 实施优先级

### P0：必须先完成

1. 新增内容模式选择；
2. 重写策略提示词，使生活化种草只生成微选题；
3. 建立四层事实/创意边界；
4. 所有自然语言输入使用统一优先级；
5. 修改提示词允许用户覆盖原策略；
6. 新增确认入库；
7. 新增终稿内容库双分区；
8. 策略候选生成前读取同模式终稿做避重。

### P1：提升稳定性

1. 结构化策略指纹；
2. 文本向量相似度；
3. 指令执行报告；
4. 业务事实与创意内容溯源；
5. 策略改变自动识别；
6. 内容库筛选和详情页。

### P2：运营增强

1. 按人群、时刻、问题和业务承接方式查看内容覆盖矩阵；
2. 显示“哪些选题维度已经过度使用、哪些仍为空白”；
3. 根据发布后的阅读、收藏、搜索和咨询数据反哺策略；
4. 为同一主题生成系列内容，但明确每篇的差异；
5. 项目级内容节奏建议，而不是只做单篇生成。

## 13. 验收标准

### 13.1 模式分流

- 未选模式不能进入策略生成；
- 同一业务事实分别选择两种模式，生成的策略信息密度和产品曝光位置应有明显差异；
- 生活化种草策略不得默认出现完整产品介绍、价格、联系方式和逐日行程。

### 13.2 创意发散

- 输入只有“包含香港、澳门相关内容”时，模型能生成多个不同的生活问题和场景；
- 不得把扩展场景写成客户已承诺的具体服务；
- 不得虚构第一人称体验、案例、效果或实时信息。

### 13.3 用户自然语言优先

- 用户说“不要价格”，最终文案不能被默认模板补回价格；
- 用户说“换成家长犹豫视角”，修改稿必须允许改变原策略；
- 用户要求与事实冲突时，界面明确显示未执行项和原因；
- 参考文案风格不得覆盖用户当轮要求。

### 13.4 入库与避重

- 文案确认后不会自动进入终稿库；
- 制作配图后存在独立“确认入库”动作和风险提示；
- 入库时保存文字和已有图片，但重复判断完全忽略图片；
- 显式宣传和生活化种草分池去重；
- 已入库策略不会在后续同模式候选中自动重复；
- 用户明确要求复用时可以覆盖默认避重，并留下记录。

### 13.5 平台适配

- 标题与正文主题一致；
- 生活化内容对用户本身有价值，不依赖产品信息才能成立；
- 不自动伪装素人或捏造体验；
- 涉及商业合作、购买链接或咨询组件时展示商业可识别性提醒；
- 发布前展示 AI 辅助创作和账号身份相关提醒。

## 14. 相比原方案进一步优化的建议

用户原方案的方向是正确的，建议额外加入以下三点：

1. **不要让模型无限制“脑补事实”，而是明确允许发散的类型。**这样既释放香港、澳门相关创意，也避免生成不存在的行程和案例。
2. **避重应比较策略，不只比较成稿字面。**换一套说法但仍是同一个人群、问题和卖点，运营上依然是重复内容。
3. **确认文案与确认入库必须分开。**前者服务配图，后者代表正式纳入内容资产和避重范围，语义不同。

最终建议的产品定位不是“自动生成一篇完整广告”，而是：

> 从真实业务出发，持续发现不同的生活问题，用一篇一个小角度的方式，建立可积累、可避重、可追踪的小红书内容资产。
