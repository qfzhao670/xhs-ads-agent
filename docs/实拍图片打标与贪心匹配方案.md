# 实拍图片打标与贪心匹配方案

## 目标

实拍图不再因为“与业务素材或当前文案不够相关”而直接被淘汰。系统先客观打标，再按当前文案对图片排序，尽可能选择最合适的图片生成可编辑初稿。

## 一、实拍图片打标

打标阶段只负责描述图片本身，不做“相关 / 不相关”的结论。

保存以下信息：

- 可见内容：人物、物品、动作、环境和画面中可确认的文字。
- 场景标签：校园、教室、户外、活动现场、合影等。
- 主体与动作标签：学生、教师、产品、讲解、互动、合影等。
- 视觉标签：横竖方向、景别、主体位置、画质、主要颜色和留字区域。
- 业务上下文：可选。记录用户确认的活动、项目或拍摄批次，不由模型仅凭业务原始素材推断。

业务原始素材可以帮助统一用词，但不得把图片中不可见、用户也未确认的信息写进客观标签。

## 二、按当前文案进行匹配排序

生成宣传图时，所有“已启用且已完成打标”的图片都进入候选池。系统逐张判断并排序，不再先做硬筛选。

匹配等级：

- `direct`：直接展示文案中的对象、活动、过程或细节。
- `supporting`：能够自然辅助文案中的具体场景或观点。
- `contextual`：画面不展示具体产品，但属于同一活动或可表达参与者、氛围、团队等上下文。
- `fallback`：联系较弱，但在现有素材中最接近当前文案。
- `conflicting`：与文案事实明显冲突，不得使用。

排序依次考虑：文案内容相关度、已确认的业务上下文、画质与排版适用性、与已选图片的内容互补性。

## 三、贪心选图

1. 先选择与当前页面主题最相关、最能独立表达内容的图片。
2. 再选择能补充全景、人物、动作或细节的图片。
3. 避免重复选择内容和构图高度相似的图片。
4. 每张图片单独保存匹配等级、对应文案依据和选择理由。
5. 优先使用 `direct` 和 `supporting`，不足时依次使用 `contextual` 和 `fallback`。

## 四、弱相关兜底

- 没有强相关图片时，仍生成最佳可用方案，不因匹配不足中断流程。
- `contextual` 和 `fallback` 图片只用于氛围、参与者或辅助页面，不用于证明具体产品功能、效果或业务事实。
- 页面标记“相关性较弱，建议确认”，允许用户换图或调整标题。
- 即使自动方案没有合适图片，也应创建空白宣传图任务，让用户手动选图。

## 五、硬排除条件

仅在以下情况排除图片：

- 图片被用户停用或尚未完成打标。
- 图片损坏、无法读取或画质不可用。
- 图片内容与当前文案存在明确事实冲突。
- 图片存在不适合发布的明显风险内容。

核心原则：**打标只描述，匹配只排序，贪心选最优，弱相关可兜底，明确冲突才排除。**
