| 节点编号 | 节点名称 | 节点具体会怎么做 | 这么做的原因 |
| --- | --- | --- | --- |
| 01 | 创建并初始化本地项目 | 用户先在自己的电脑上新建一个空文件夹，然后在软件中选中该文件夹作为本项目的保存位置。系统检查该路径是否可读写，并在用户确认后初始化项目所需的配置和数据文件。每个业务单独使用一个项目文件夹，其原始素材、关键词库、高表现参考文案库、合规性准则、生成策略、终稿和修改记录都保存在该文件夹内。用户后续可重新选择已初始化的项目文件夹继续编辑和生成，不需要重新导入整个项目资料。 | 将不同业务分别保存在独立本地项目中，可以避免关键词、参考文案和合规规则串用到其他业务。保存位置由用户自己选择，用户能够明确知道项目文件在哪里，也方便备份、迁移和长期维护。 |
| 02 | 在项目内管理输入资料 | 原始素材仍通过 Markdown 文件导入：用户先借助 Codex、豆包等工具，将客户提供的 PDF 和图片完整转换成 `业务原始素材.md`，再在前端上传。该文件是生成任务的必需输入，系统将其复制或保存到当前项目文件夹。关键词库、高表现参考文案库和合规性准则不再通过 Markdown 文件上传，而是分别在前端页面中逐条新增、查看、修改和删除，所有变更都自动保存到当前项目文件夹。高表现参考文案每条至少保存完整标题和正文，可选保存作者/账号、内容类型、表现数据、备注等信息。系统在新增记录时生成项目内唯一、稳定且持久化的编号，例如参考文案使用 `REF-0001`、关键词使用 `KW-0001`、合规准则使用 `RULE-0001`。编号由系统生成，不因页面排序、内容修改或重新打开项目而变化；记录被删除后，原编号不分配给新记录。未录入关键词、参考文案或合规准则时，不阻断流程，只是后续无法使用对应的增强内容。 | 关键词、参考文案和合规准则都是会持续积累和反复使用的项目资产，如果每次都靠 Markdown 文件整体上传，用户很难精准修改单条内容，也容易产生版本混乱。前端逐条管理加项目内持久化保存，更适合长期运营和分项目复用。稳定编号还可以让策略、生成记录和终稿始终指向同一条项目数据，不再依赖易变的文件顺序或临时编号。 |
| 03 | 提取、确认并形成业务事实（第一阶段大模型调用） | 将当前项目已导入的 `业务原始素材.md` 交给大模型，让模型根据素材实际包含的内容开放式提取业务事实，并对事实进行归类、去重和整理。提示词可以列出产品、人群、场景、卖点、服务、流程、价格、时间、地点、名额、资质、安全、权益和限制等作为“可能需要关注的内容”，但它们不是固定必填字段；素材里有什么就提取什么，不因素材没有某一类内容就判定为“信息缺失”，也不要自行补全素材中没有的信息。模型同时区分“可确认事实”、“宣传性表达”和“存在冲突的事实”。如果不存在冲突，则直接输出完整的业务事实；如果发现同一事项在素材中存在不同口径，则暂停后续流程，以简短、明确的问题询问用户以哪个口径为准。用户给出标准后，将“原始素材 + 已发现的冲突 + 用户确认的标准”再次输入大模型，让模型重新生成一份消除冲突后的完整业务事实，并将该事实结果保存到当前项目文件夹。 | 事实提取应该以素材实际包含的信息为边界，而不是用一个预设字段表反向要求所有业务都必须提供相同信息。建议性的提取类别可以帮助模型少漏读，但不应制造虚假的“缺失项”。对于真实存在的口径冲突，模型无权自行选择，必须由用户确认后再重新生成统一、完整的事实上下文。 |
| 04 | 读取项目资产并生成简要策略候选（第二阶段大模型调用） | 系统从当前项目中读取节点 03 得到的完整业务事实，以及当前项目关键词库、高表现参考文案库和合规性准则中的现有记录，将它们拼接为一个提示词，不分别调用模型做关键词分析、参考文案拆解或合规规则转换。调用一次大模型，让模型在该次调用中理解所有现有输入并给出 3–5 个彼此明显不同的文案策略。每个策略只选择真正适合该方向的参考文案，一般为 1–3 篇，上限为 3 篇，不为了增加参考数量而勉强关联；多个策略可以合理地复用同一篇参考文案。前端将每个策略显示为一张 4–6 行的简短策略卡，只包含：①策略名称；②一句话核心切入角度；③主要使用的 2–4 个素材点；④一句话写作路线；⑤参考文案，按“系统编号 + 文案标题”列出本策略准备参考的 1–3 篇高表现文案，没有参考文案时显示“无指定参考文案”；⑥该策略最适合的目标。策略与其引用的系统编号一起保存到当前项目文件夹。 | 在参考文案库中使用项目内稳定的系统编号，比按文件顺序临时编号更适合长期的增删改查和分项目管理。每个策略只引用少量、高相关的参考文案，既方便用户判断写法来源，也为终稿阶段精准读取对应参考原文提供可靠索引。 |
| 05 | 用户选择策略并补充建议 | 向用户展示节点 04 输出的简短策略卡。用户必须从中选择一个策略，不支持同时选择或自动合并多个策略。选择时，用户可以额外输入文本建议，例如调整人群、卖点、语气、篇幅、必写信息、不写信息、关键词或结尾方式。用户未选择策略时，不进入文案生成。 | 单选可以保证每篇文案只有一条清晰的内容主线，避免多个策略拼在一起后重点过多。允许补充文本建议，可以在不破坏主线的前提下体现用户的具体偏好。 |
| 06 | 根据选定策略生成终稿（第三阶段大模型调用） | 系统读取用户选中的唯一策略，根据策略中保存的参考文案系统编号，从当前项目的高表现参考文案库中只读取对应的 1–3 篇完整文案。未被该策略选中的参考文案不加入本次成稿提示词。将节点 03 得到的完整业务事实、用户选中的唯一策略、用户的额外文本建议、当前项目的关键词库和合规性准则，以及上述精准选中的参考文案一起拼入成稿提示词，调用一次大模型直接生成终稿。默认终稿包含标题、正文和话题标签。模型必须遵循选定策略的核心主题和信息取舍，只使用已形成的业务事实；将适合的项目关键词自然融入标题、正文或话题标签，不机械堆砌；对于选中的参考文案，重点模仿其选题方式、钩子、结构、节奏和语感，但不直接复制原句或移植其业务信息；同时遵守当前项目中的合规性准则。生成的终稿与本次使用的策略编号、参考文案编号和修改版本一起保存在当前项目文件夹。 | 每个策略的写法方向不同，终稿生成时只需要传入与所选策略高相关的少量参考文案，而不是重复读取整个参考库。通过项目内稳定编号精准查询，既能让模型更聚焦地模仿对应写法，又可以减少无关信息干扰、上下文长度和调用成本。 |
| 07 | 人工确认或提出修改要求 | 向用户展示节点 06 生成的终稿。用户可以选择“确认”，此时该版本成为最终输出；也可以输入新的文本要求，例如更换标题方向、删减某段、强调某个卖点、调整语气或篇幅。提出新要求后，将“当前终稿 + 新要求 + 原有业务事实 + 当前项目关键词库 + 当前项目合规性准则 + 该策略选中的参考文案”送回节点 06，再调用大模型修改，仍不传入未被该策略选中的其他参考文案。每次修改后都回到本节点等待用户确认，同时将每次修改版本保存到当前项目文件夹。 | 大模型生成的文案不应默认为已可发布。人工确认是最后决策点；在修改循环中继续使用同一策略选中的少量参考文案，可以避免修改过程逐步偏离已确认的写作方向。保留历史版本也便于对比和回退。 |
