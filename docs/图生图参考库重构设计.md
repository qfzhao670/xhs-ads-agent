# 小红书配图：参考图库驱动的图生图重构

## 目标

配图链路不再允许无参考图的文生图请求。用户维护一个项目级“小红书图片参考库”，系统先用视觉理解模型为图片生成文字标签，再由文案模型按当前文案逐页召回参考样本，最后将样本与本篇事实提示词一起传给 Qwen Image 执行图生图。

参考图片是第三方内容，只能提供版式、构图、配色、字体气质、留白、材质和视觉节奏。人物、商品、品牌、文字、地点、价格、数据和活动权益必须根据当前项目事实重新生成，不能从样本继承。

## 完整链路

```text
用户上传优秀图片并标注封面/内容页
                │
                ▼
视觉模型生成结构化标签
（场景、风格、构图、排版、配色、关键词）
                │
                ▼
文案模型读取当前事实、终稿和全部生效标签
为套图每一页选择 1–3 个 referenceImageIds
                │
                ▼
读取对应本地图片并转为 Base64
                │
                ▼
Qwen Image I2I
参考图 + 当前事实提示词 + 真实性边界
                │
                ▼
保存生成图片、引用来源、提示词和请求元数据
```

## 数据模型

参考库保存在 `项目数据/小红书图片参考库.json`，原图保存在 `项目数据/小红书图片参考库/`。每条记录包含：

- 稳定编号 `XHSIMG-0001`；
- 本地相对路径、原文件名和尺寸；
- 用户标注的 `isCover`；
- 生效状态和打标状态；
- `summary`、`useCases`、`visualStyle`、`composition`、`textLayout`、`colorPalette`、`keyElements`、`keywords`、`avoidCopying`。

套图策划的每一页保存 `referenceImageIds`，每张生成图也保存本次实际使用的 `referenceImageIds`。因此历史结果可以追溯到具体 few-shot 样本，而不是只留下不可解释的提示词。

## 接口约束

- DashScope 同步接口：参考图作为 `messages[0].content` 中的 `image` 对象，文本指令放在最后一个 `text` 对象。
- OpenAI 兼容接口：参考图放在 `/images/generations` 请求体的扩展字段 `image`。
- `qwen-image-3.0` 每次最多传 3 张图；当前策划层也限制每页 1–3 张。
- 图生图只使用 `prompt_extend_mode=direct`；不再暴露不兼容的 Agent 模式。
- 没有可用参考图时，请求构造器直接报错，不允许静默降级为文生图。
- 上传图片限制为 10MB、边长不超过 8000 像素、长宽比不超过 10:1。

## 失败与恢复

- 打标失败不会丢失原图，卡片展示具体错误并允许重新打标。
- 停用的图片不会进入新的参考召回。
- 生成中断后，已经完成的页面保留；再次执行时只生成缺失页面。
- 旧版纯文生图策划没有 `referenceImageIds`，再次生成套图时会自动重新策划并选择参考图。

## 真实性保护

真实性边界同时存在于两个模型阶段：

1. 策划阶段明确要求参考标签只参与视觉匹配，页面内容只能来自业务事实和已确认文案。
2. 出图阶段逐张声明输入图片是第三方视觉样本，禁止复制其人物身份、商品、品牌、Logo、原文、地点、价格、数据和权益。

这两层约束不能完全替代人工审核，但可以避免把“参考图片中的事实”误当成“本项目的事实”。
